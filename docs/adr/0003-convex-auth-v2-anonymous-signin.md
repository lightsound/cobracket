# Adopt Convex Auth v2 (preview) with Anonymous Sign-In

Superseded by [ADR 0031](./0031-adopt-spacetimedb-as-the-backend.md) (2026-11-15): the backend is SpacetimeDB, and identity is the server-issued Identity bound to an app-owned user row — no auth library, no sign-in provider, no keys. What carries over is this ADR's intent and shape: anonymous-first identity, auth isolated behind the single client module, and an upgrade to a full account later — the account is ADR 0021's email code, restated in ADR 0031.

Amended by [ADR 0021](./0021-email-code-sign-in-and-reachable-organizers.md): the upgrade to a full account is an email one-time code built on the v2 core, a known email merges the anonymous identity into the account, and MCP tokens are issued only to accounts with a verified email. Amended by [ADR 0024](./0024-organizer-side-requires-an-account.md) (2026-10-14): the whole Organizer side — creating or operating a tournament, an Event, or a Community — requires an email account, so the zero-sign-up promise below no longer applies to Organizers; the anonymous identity remains the Registrant-side identity (anonymous-allowed Tracks — one-player ones only since 2026-10-22, ADR 0029 — and their claim links), and the single auth module this ADR prescribes stands.

Organizers must be able to create a tournament with zero sign-up friction. We adopt Convex Auth v2 — still a preview — and use its Anonymous Sign-In: an anonymous user owns the tournaments they create and can later be upgraded to a full account. The preview-stage risk is accepted deliberately: the project is not shipping to production imminently, we want to stay as close to Convex as possible, and first-class anonymous-to-account linking beats a hand-rolled secret management-link scheme.

## Consequences

- Auth is isolated behind a single module (e.g. `src/lib/auth`) that exposes only "who is the current Organizer" — and, from ADR 0021 (amended 2026-10-14), sign-in, the merge, sign-out, email change, and account deletion, still through that one seam; ImportLint enforces the boundary. If Auth v2 stalls or changes shape, that one module is swapped (Convex Auth v1 or an external IdP) without touching the app.
- MCP clients cannot reuse the browser session, so the MCP server authenticates with a token issued from the web UI instead — to an account with a verified email only (amended 2026-10-14, ADR 0021 and 0024: every Organizer is an email account, so there is no anonymous Organizer to attach one first).
