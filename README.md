# cobracket

cobracket lets anyone easily host and manage a tournament of any format — from the web, or from chat (MCP). Product direction: [`docs/vision.md`](./docs/vision.md) · domain glossary: [`CONTEXT.md`](./CONTEXT.md) · decisions: [`docs/adr/`](./docs/adr/) · current spec: [`docs/specs/mvp.md`](./docs/specs/mvp.md).

The codebase is currently a minimal [Solid 2.0](https://v2.solidjs.com/) setup based on the official `bare` template (plus a Convex task-list demo), serving as scaffolding to be replaced per the MVP spec.

The package manager is **Bun v1.4**.

## Requirements

- [Bun](https://bun.sh) 1.4.x

```bash
curl -fsSL https://bun.sh/install | bash -s "bun-v1.4.0"
```

## Usage

```bash
bun install
bun run convex:dev
bun dev
```

`convex:dev` starts a local Convex backend and writes `VITE_CONVEX_URL` into `.env.local`. Run `bun dev` in another terminal and open [http://localhost:3000](http://localhost:3000). Editing `src/App.tsx` hot-reloads.

| Command | What it does |
| --- | --- |
| `bun run convex:dev` | Local Convex backend (function watch / type generation) |
| `bun dev` / `bun start` | Vite dev server |
| `bun run build` | Build the static site into `dist/client` |
| `bun run serve` | Preview the production build locally |
| `bun run fallow` | Static analysis for unused code, duplication, complexity ([Fallow](https://github.com/fallow-rs/fallow)) |
| `bun run fallow:audit` | Gate only the changed diff |

## Structure

There is no `index.html` and no mount entry file. The turnkey mode of `@solidjs/vite-plugin` (the `start` option of `solid()` in `vite.config.ts`) generates the entries from these files:

- `src/App.tsx` — the app itself (Solid demo)
- `src/Tasks.tsx` — the Convex task list
- `src/Document.tsx` — the HTML shell (title / meta / favicon)
- `src/lib/convex.ts` — the `ConvexClient` from `convex/browser` and query subscriptions for Solid 2
- `convex/` — schema and queries / mutations. `convex/_generated/` is generated by `bun run convex:dev` and is checked into the repository

`bun run build` prerenders the shell into `dist/client/index.html`, producing an artifact deployable to any static host as-is.

For streaming SSR, add `ssr: true` in `vite.config.ts`.

The backend is [Convex 1.45](https://docs.convex.dev/). To connect to the cloud, run `bunx convex login` and then choose a deployment via `bun run convex:dev`.

## Code quality

[Fallow](https://github.com/fallow-rs/fallow) 3.20 checks for unused files / exports, circular dependencies, duplication, and complexity. Configuration lives in `.fallowrc.jsonc`. All rules are `error` in principle; the only rule currently off is `coverage-gaps`, because execution paths cannot be verified without tests. TypeScript semantic analysis (`typeAware`) is on. Solid 2's start mode has no `src/main.tsx`, so `src/App.tsx` and `src/Document.tsx` are set as entries. `convex/_generated/` is excluded from analysis.

For coding agents, `bunx fallow agent install` wires up the skills (`.agents/skills/fallow`, `.claude/skills/fallow`), MCP servers (`.cursor/mcp.json`, `.mcp.json`), and the Claude Code commit/push gate. Re-running it is byte-stable (no diff).

```bash
bun run fallow
```

GitHub Actions (`.github/workflows/fallow.yml`) runs the same analysis over the whole repository and fails on any issue.

For details, see the [Solid 2 docs](https://v2.solidjs.com/) and the [Convex docs](https://docs.convex.dev/).
